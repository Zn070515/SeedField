# MASTER GDD —《种子域》全游戏概要设计

> 面向想在 10 分钟内理解全作品的开发者/Agent。本文件是导航概要；精细规则请读各子系统文件，权威决策请读 `DECISION_REGISTER.md`。

## 游戏身份

《种子域》（SEED FIELD）是一款 Windows 优先、Steam 付费、可完全离线运行的二维编程文明沙盒。玩家在主控崩溃已久的数字世界，操作一个不可毁的种子核心区，从五个基础分支的构造出发，逐渐建设能源、物流、通信、计算与战斗网络，组织大量可自主运行的设备，在多个区域中与其他玩家的离线文明版本发生竞争、合作与战争。达成不同文明级终局后，仍可继续游玩。

## 核心玩家幻想

不是靠手动指挥 1000 个单位赢，而是设计某种协议/设备，使得大量单位在各自感知受限、能量/算力有限、消息不即时的条件下，仍能自主完成复杂目标。玩家通过观察系统涌现的行为，反复修改程序和物理部署。

## 世界与规则

- **空间**：多个相连区域，每区真实二维场地，通道/网络承载各自合法能力；不允许跨区域免费瞬移物质。
- **历史**：中央主控崩溃很久，自治种子文明已成熟；玩家作为弱小协议设计者入场。
- **资源**：E 能源（可积累、网络供给）、M 基质（可积累、简化物流），C 算力/S 存储/B 带宽为分布式容量约束。
- **执行**：JavaScript + Jint 4.18.0 控制器，观察由 C# 过滤，动作由统一 C# 固定 Tick 仿真核验证；玩家程序、内置/导入文明都不能直接修改真状态。
- **对抗**：其他玩家的离线文明版本，本地自主运行；不需要原作者在线，不需要开发者服务器。首发必须有内置对手。
- **存续**：玩家不可毁的种子核心区永久保存原始种子和能源/感知/通信/状态/执行五分支最新已确认产品，低速不可断地再生基础 E/M；外部资产可全毁，但总可重新建设。
- **终局**：多种文明级目标；达成后世界继续运行。具体任务未冻结。

## 开局路径

最少满足五个基础分支：能源、感知、通信、状态、执行。每个只需证明“能用”，不能强制要求高效率、高级材料或学会 JS。教程结束就进入 PvE；之后构造关卡用 AND/OR 前置仅引导更高级的构造能力。工坊和代码编辑默认暂停，可主动实时；蓝图改动与实际部署更新分离。

## 设备与文明成长路径

初期的独立设备 → 多个协作体 → 供电/通信/物资网络 → 自主生产与守卫 → 模块化战构体 → 多区域扩张 → 技术探索/构造验证/高级编程 → 与其他离线文明动态竞争 → 文明级终局与开放沙盒。物理设备的能源、质量、感知、算力、存储、带宽和武器都有真实代价，而不是纯外观。

## 玩家交互

1. 在地图中感知可达信息并设定目标。
2. 在工坊完成装配、产品封装和版本化保存。
3. 用 JS 控制器设定自治决策；查看局部观察、消息、内存、动作与错误。
4. 在世界中制造/部署/升级实际实例。
5. 让设备在真实能源、物流、通信与对手竞争中运行。
6. 分析资源瓶颈、程序不良行为、设施损毁，再修订设计。

## 用户体验与商品品质

- 30–60 分钟首次正式战斗是设计目标，尚需试玩验证。
- 非编程玩家可用基础模板走通前期，程序高手有深度函数与协议空间。
- 画面以精致 2D、Blender 预渲染和 Shader 为基准；不是永久线框占位。
- 需有可理解的故障诊断、真实视觉反馈、存档/回滚、完整离线内置内容。

## 工程栈

`Godot 4.7.2 .NET（.NET 10.0 构建目标）→ C# SimulationCore → JavaScript/Jint 4.18.0 → TypeScript .d.ts editor declarations`，统一事件/状态模型支撑关卡、自由世界、回放、测试。无必要的在线后端、无服务器账号、无实时匹配要求。

## 开发节奏

M0 技术与视觉原型 → M1 五分支/工坊 → M2 能源/资源/计算/通信 → M3 多区域与永久复建 → M4 战构体与 PvE → M5 文明长期运行 → M6 内容/美术/UX → M7 多终局与 Steam 发布 → M8 维护/可选 UGC。验收以**实际运行证据、试玩与安全回归**，非提交量和测试数量。
