# UX、调试、信息设计、音效与可访问性

## 原则

游戏的复杂度应来自玩家设计系统，而非菜单难找、隐藏状态或无意义操作成本。玩家必须理解设备的**输入—决策—意图—结算—反馈**链路，才有动力继续编程和优化。

## 必需 UI 视图 [PROPOSED]

| 页面/叠层 | 核心任务 | 诊断信息 |
|---|---|---|
| 世界/区域 | 建造、探索、指挥、观察文明事件 | 能源/物流/通信/威胁可切层 |
| 种子核心区 | 查看五分支最新产品、保底资源、复建 | 当前可复建项、所需时间/成本 |
| 工坊 | 选择元件、连接装配、保存蓝图、验证 | 模块接口、预算、兼容性、错误 |
| 程序编辑器 | 编写 JS、补全、运行与升级 | 行号错误、预算、局部内存/观察 |
| 单位调试器 | 解释行动与失败 | Observation / Inbox / Memory / Intent / Result |
| 文明与战略 | 对手、区域、发展方向、关系 | 当前掌握的情报、战略目标 |
| 研究与构造关卡 | 探索能力和验证新功能 | AND/OR 前提、已验证项 |
| 存档/对手包 | 导出版本、导入内置/文件包 | 兼容性、安全/运行状态 |

## 操作体验 [BASELINE]

- 工坊与代码编辑默认暂停世界，但允许显式恢复实时运行。
- 实时任务/命令和程序版本部署要遵守通信/可部署条件。
- 自动控制的失败应有结构化诊断而不是“设备什么也没做”。
- 提供运行状态切层：电力图、数据链、物流、感知、危险范围（最后一项必须遵守玩家已知情报）。

## 可访问性 [PROPOSED]

- 不能仅靠红/绿图区分设备阵营或故障；同时使用纹理/符号/形状。
- 可调 UI 缩放、文字大小、镜头缩放与高对比信息层。
- 色盲可辨图例、键位重映射、镜头晃动和粒子强度控制。
- JS 编辑器支持键盘操作、搜索、括号匹配、错误行定位与复制诊断。
- 长时间运行需有暂停、倍速、分段统计以免沦为等待模拟器。

## 声音方向 [PROPOSED]

- 基础设备：低强度、短促的数字工业反馈；避免连续刺耳警报。
- 能源网络：稳定嗡鸣、断供瞬时音和恢复提示。
- 通信：有明确发送/接收/丢包的视觉/音效对应。
- 战斗：射击、盾击、模块破坏与高危状态具备辨识度。
- 核心区复建：低速、克制而明确的恢复反馈。
- 音效不能承担唯一信息通道，所有关键事件必须有文字/图形提示。

## 首发交互验收

- 新玩家能找到建造、能源检查、程序应用和撤销/回退的入口。
- 一次脚本失败可在 UI 上定位行号和失败原因。
- 可以看出当前查看的是“工坊最新版本”还是“世界中旧部署版本”。
- 核心区被外部全毁时，清楚提供最低复建步骤且不会因为缺失视角被卡住。
- 无论是否使用社区内容，都可以浏览和挑战内置离线文明。
