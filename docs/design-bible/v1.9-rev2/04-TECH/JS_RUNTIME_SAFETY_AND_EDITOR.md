# JavaScript / Jint 4.18.0 运行时、沙盒、开发体验

## 现行决策 [CONFIRMED]

Godot 4.7.2 .NET（.NET 10.0 构建目标）+ C# SimulationCore + JavaScript（**Jint 4.18.0**）；`.d.ts` 作为补全/API 契约。JS 不可直接改变权威世界状态。

## 标准调用抽象 [PROPOSED]

`ControllerProgram(Observation, LocalMemory, Inbox, GameComputeBudget) -> Intent[] + NewLocalMemory + Diagnostics`

- 不传 .NET CLR 句柄、真正世界实体对象或可执行宿主 API。
- 使用纯值序列化出入，避免 JS 对引擎内部集合的引用泄漏。
- 默认周期回调，同一控制器保留明确限定的状态数据，最大尺寸需要测定。
- JS 语法能力、时间 API、随机 API、序列化规则和异常码必须统一版本化。
- 程序按设备能力提供有类型的白名单功能，不允许没有通信模块却调用全图聊天。

## 双预算模型

| 类型 | 用途 | 绝不能混淆 |
|---|---|---|
| **游戏内 C 预算** | 玩家策略与设备硬件能力的可预测取舍 | 不能用宿主毫秒直接定价 |
| **Jint 宿主安全预算** | 防止失控循环、爆内存、深递归、异常阻塞 | 不是游戏平衡系统，也不构成强 OS 隔离 |

超额可发 `COMPUTE_BUDGET_EXCEEDED` 或 `SCRIPT_TIMEOUT` 等不同事件。具体“降频/中断/延迟/动作丢弃”尚待产品确认与原型实测。[OPEN]

## 第三方文明包安全模型（强约束）

- 先用内置可信脚本测试完整仿真。
- 未实现 OS 级独立进程执行、资源配额、最小权限、IPC schema 校验、异常隔离/恢复前，不自动执行第三方用户脚本。
- 即便 Jint 不开启 `AllowClr`，仍不可认为外部恶意 JS 已被完全隔离；需要模糊测试、异常注入和负载攻击验证。
- 外部包禁止自由访问文件、网络、系统命令、原生代码和未经审查的宿主对象。
- 对手包源代码先静态检查/大小限制/依赖清单；单次运行的结果必须只有经过验证的纯数据。
- 对第三方资源（图像/声音/文本/压缩内容）也应考虑大小限制、路径遍历和解码风险。

## 确定性注意点 [VALIDATE]

随机数必须由存档/仿真分配稳定种子；系统时间、环境区域设置和浮点非确定性不得成为局内优势。JS 需要纯可复现随机接口。`Math.random` 的具体注入方式以及 Date/动态代码能力由运行时实验核查。

## 编辑器的最低商业品质 [PROPOSED]

- JS 编辑、行号、语法诊断、设备 API 文档、`.d.ts`、自动补全、语义示例。
- 可查看设备本地观察、消息收件箱、持久记忆、动作输出、脚本错误和消耗预算。
- 固定种子对照测试，编辑与世界运行默认暂停，可主动实时。
- 一次点击应用/回退到具体世界实例，部署需要满足权限/通信/资源条件。
- 模板降低门槛，但高级玩家可编写真实函数和协同协议。

## 重要的性能基准 [VALIDATE]

分别在 10、100、300、500、1000 控制器条件下测：单 Tick CPU 时间（均值/P95/P99）、Jint 引擎内存、创建/恢复状态开销、GC 停顿、数据序列化开销、脚本异常的尾延迟。测试应在目标最低配置与目标常用配置运行；高端开发机单点数据不代表商业性能达标。

## 先验要求

任何技术文档关于某 Jint API 的调用签名、语句限制机制都必须通过 **4.18.0 精确版本**编译/运行验证，不得拿其它版本的网上示例直接贴进生产代码。
