# 离线 PvE：其他玩家的文明版本

## 核心定位 [CONFIRMED]

本游戏是**完全离线运行的单机 PvE**。主要对手的**设计来源**是其他玩家的离线版本：可携带设备、程序、协议和发展策略等内容的包，导入到某个本地世界后自行决策与运行。**不是录像回放，也不是等待作者在线操作。**

开发者**没有预算运营自己的游戏服务器**，因此世界运行/战斗/文明发展/存档必须全在玩家本机；任何账号、全球文明同步或在线匹配都不得作为核心功能前提。[CONFIRMED]

## 合理的离线包生命周期 [PROPOSED]

1. 作者在自己的本地世界/工坊建立若干蓝图、JS 控制器、协议与可复用战略配置。
2. 作者选择版本、可导出的能力范围以及依赖资产，生成**有版本的静态离线文明包**。
3. 开发者内置示例或用户通过本地文件交换取得包；未来可选 Steam Workshop。
4. 当前玩家将包载入，先进行结构、版本、安全兼容检查。
5. 系统实例化包内的合法设计，赋予本地世界的初始资源/区域/情报。
6. 从此以后，对手在**本地存档**中自主决策、采集、部署和战斗（具体战略自治程度尚待批准）。
7. 包作者后来更新自己的作品不会强制篡改已经存在的本地文明；升级须显式操作并兼容迁移。

## 内置文明的重要性

正式游戏必须有足够内置对手，让完全没联网、没人上传社区内容的玩家也能体验完整战役和多文明世界。开发者可以用与玩家相同的工坊/程序机制制造这些内容，避免“对手数值作弊”成为默认难度来源。[CONFIRMED/BASELINE]

## 形态分层（未决，建议保留能力位）

| 形态 | 用途 | 内容 |
|---|---|---|
| 战术对手 | 防御与小队挑战 | 机体+局部控制程序+有限行动目标 |
| 工程对手 | 攻防与生产挑战 | 部署蓝图+资源/物流策略 |
| 文明对手 | 持续区域竞争 | 长期经济+扩张+研发/外交/战术策略 |

以上分层是便于优化和内容制作的**推荐架构**，不是用户已选择的首发三档模式。游戏愿景是多文明持续演化；每档的开发和发布范围需通过试玩控制。

## 公平性

- 所有实际动作需通过同一 `Observation → Intent → SimulationCore`。
- 对手不能看到玩家隐藏位置、绕过资源成本或修改 C# 真状态。
- 可以给予公开可见的非对称初始资源和区域位置，不能在运行时偷偷加资源来补偿 AI 弱势。
- “玩家永久种子核心区”是专门确认的保护规则；对手核心是否相同仍为 `[OPEN]`，不得在包系统中写死一方。

## 分发边界

**首发可行**：内置包 + 本地导入/导出静态文件。**以后可选**：Steam Workshop / UGC。**不做**：自建内容平台、持续在线对手云算力、强制账号、在线排行榜、后端数据库。

## 安全闸门

导入的包只要含有可执行 JS，就属于不可信代码。Jint 语句/超时/内存限制不等于恶意脚本隔离。**未实现独立进程沙盒和可信 IPC 前，第三方 JS 执行功能保持关闭**，可以先只读元数据/显示设计；内置审查脚本可用于研发。[BASELINE]

## 数据边界

- **包版本**与**文明存档实例**分离：导入包是模板，世界实例拥有自己的可变状态。
- 需要清单、内容哈希、版本/兼容范围、许可/来源、规模限制和依赖声明。[PROPOSED]
- 包必须能完整离线验收与导入，不能在运行时偷偷请求 URL 加载依赖。
- 不允许无授权读取作者本地保存的个人资料/文件或玩家的系统路径。
