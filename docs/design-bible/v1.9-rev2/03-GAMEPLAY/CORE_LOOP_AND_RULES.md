# 完整游戏循环与统一规则

## 主循环 [CONFIRMED 方向]

**观察与发现 → 设计与构造 → 验证与编程 → 制造与部署 → 自主运行 → 资源/信息/战斗反馈 → 优化与扩张**。这个循环在单设备、基地、区域和多文明四个尺度上都成立。

玩家通过改变**规则、网络和硬件配置**实现策略，而不是持续微操每个单位。

## 四个尺度

| 尺度 | 基础问题 | 玩家创造的东西 |
|---|---|---|
| 元件/设备 | 如何让一个实体正确感知与行动？ | 五分支结构、机体配置、低级控制器 |
| 小队/工厂 | 多个实体如何协作、交换消息、供能？ | 控制程序、物流、通信协议、模块组合 |
| 区域 | 如何在有限供给下防御、扩张、获取资源？ | 区域设施、供能链、中继、自治生产网络 |
| 文明/跨区域 | 如何长期面对其他玩家离线文明的适应性策略？ | 多区域系统、发展战略、对抗/合作网络 |

## 玩家能做什么

- **构造**：通过工坊组合元件、模块与设备，保存可复用产品架构。
- **研究**：探索区域/遗迹取得知识，并通过构造验证与编程把高级能力变成现实。
- **编程**：基于 JavaScript 控制局部感知、移动、目标选择、通信、状态机、协同等。
- **建设**：采集/制造/存储基质，建立发电、供电、中继、生产和军事设施。
- **部署**：把工坊版本安装到具体世界实例；老设备不因修改蓝图自动改写。
- **指挥**：制定目标、区域策略、升级安排；通信中断时自治程序仍按本地信息行动。
- **探索/外交/战争**：与多个离线文明接触、交换信息/资源或争夺区域。
- **恢复**：外部基地全毁依然能靠不可摧毁的种子核心区和保底 E/M 重新发展。

## 不变量 [CONFIRMED/BASELINE]

1. 行动意图并不直接决定结果；仿真核验证实体状态、能量、合法目标、作用范围、模块能力和时间。
2. 信息不能免费全图共享；感知、通信和历史信息拥有不同有效性。
3. 物质不能无成本跨区域使用，能源不因为在全图某处生产就默认随处可用。
4. 玩家与对手的**活动实体行动**都通过同一合法性验证，不依赖渲染结果。
5. 战败不会彻底剥夺玩家最低复建能力，但会真实损失外部成果。
6. 世界更新不能依赖图形 FPS；统一固定 Tick 和事件模型。
7. 任意模式的基础元件和模拟规则一致；模式允许不同初始条件与难度设定。[BASELINE]
8. 多终局之后仍可保持建设、探索和其它系统循环。[CONFIRMED]

## 候选规则时序 [PROPOSED，不固定实现]

按整数 Tick 处理：

1. 收集上 Tick 到达的消息/已经生效的事件。
2. 生成每个实体允许观察到的 Observation。
3. 执行程序/策略控制器，形成 Intended Actions（预算内）。
4. 验证动作及其依赖状态，应用费用/优先级/冲突规则。
5. 结算移动、供能、生产、物流、战斗和发出的消息（具体依赖序由测试决定）。
6. 写入状态变化和只读事件，提交可渲染快照。

**注意**：不同系统间具体先后顺序必须统一测试，例如“本 Tick 发出的消息不能本 Tick 被使用”“移动后开火还是开火后移动”“同一库存同时建造时的资源竞争”。不得让不同模块私自调用世界更新。

## 训练与挑战 [PROPOSED]

建议提供无战役消耗的测试场地：固定种子、可比较程序差异、显示能耗/伤害/信号/延迟，允许保存运行结果和回放。此功能对玩家深度编程是重要的可用性工具，但不应另建一套冲突规则。
