# 全生命周期场景验收样例

> 所有示例属于设计说明与测试用例，不是已编写执行过的测试。最终名称和数值可变，但断言意义不能变。

## S1 五分支最低教程

给一个合法但低效的能源、感知、通信、状态与执行组合。通过最低功能验证后，玩家可以直接进入第一个 PvE 区域；即使尚未解锁高级研究或不会 JS，也能使用基础模板继续发展。

## S2 程序真正在改变战斗

在固定资源、相同场景/机架/种子的条件下，让 JS A 优先攻击最近敌人，JS B 优先集火威胁最高的目标。记录不同的 Intent、弹道、能耗、损伤与胜负；游戏必须解释差异，不得硬编码某版本必胜。

## S3 断联与局部知识

两个己方设备由一条中继链路相连。侦察设备发现敌人后发送消息；断开中继，接收方不能继续获取新敌方位置，但可在本地依旧有传感器/记忆/程序时自主行动。

## S4 程序崩溃与宿主安全

一个 JS 控制器死循环、访问禁止 CLR、尝试异常分配。仿真应在宿主级约束内安全拒绝/回退该控制器，保留其它设备和真实 WorldState 一致性；对第三方包需额外 OS 隔离。

## S5 蓝图与实例版本

在工坊将传感器/程序从 v1 改为 v2；世界已部署设备仍引用 v1。玩家显式执行合法升级后部分设备切 v2，其他设备仍旧，日志与 UI 能区分。

## S6 多区域能源和 M

A 区发电、生产/采集 M，B 区有建设请求。切断特定能源/物资连接，B 区不能立即获得 A 区新的能源/材料。重新连接并完成合法运输后才允许消费。

## S7 外部全毁后的复建

对玩家存档实施极端清空：外部军队、工厂、供电、通讯、M/E 库存全部毁灭。玩家不可毁的核心区仍在，五分支最新已确认产品和保底再生 E/M 仍有效。经有限恢复步骤后可以重新部署一个最低可执行实体；不能出现死锁或需要不存在的外部工厂才能恢复。

## S8 资源套利与堵门

尝试从核心区无限导出保底资源，在长时间仿真中积攒战略工业库存；按预计设计应无法绕过其低产能/用途限制（具体平衡机制待批）。敌对势力堵住所有出口时，应有合法不失去复建的路径（机制待定，不得声称测试已完成）。

## S9 离线文明包本地运行

完全断开网络，在本机加载内置文明版本，让它在玩家可见的区域内采集/守卫/争夺中继并作出与局部信息一致的反应。作者没有在线，仍应运行。导入未知 JS 时如果 OS 隔离未完成必须安全拒绝执行。

## S10 文明长期演化

保持玩家无新手动命令，推进多个区域一定 Tick 数；其它文明在不作弊的前提下消耗 E/M、受通信限制、根据本地发展策略活动。若没有任何动态变化，应视为产品闭环不足（严格行为模型待后续设计）。

## S11 终局后仍然可玩

触发某条文明级终局条件后生成持久改变，保留世界存档；玩家继续建设、修改 JS、探索区域，其他合法事件继续结算。

## S12 精致画面与诊断

在正式 Godot 画面，玩家点击一次失败的移动/射击，看到单位知道的信息、错误码、能量预算、来源消息、部署版本和真实战斗效果。画面在密集设备/小缩放场景仍能识别主要状态。
