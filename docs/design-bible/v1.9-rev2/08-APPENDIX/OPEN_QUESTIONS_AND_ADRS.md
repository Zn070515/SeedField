# OPEN QUESTIONS / ADR — 非阻断疑问、必须标注的假设

> 本文件尤其重要：**“暂未决定”并不代表允许 Agent 替用户冻结。** 可以选择原型可替换默认值，但要写清楚替代方案和退出证据。用户当前要求直接开工，因此不要把这些问题逐条重新追问后才写第一行代码。

## 产品级待定（影响完整游戏，但非 M0 阻断）

| 编号 | 问题 | 当前已知边界 | 需要何时确定 |
|---|---|---|---|
| OPEN-01 | 其他离线文明是否也拥有不可摧毁核心区？ | **只有玩家核心区永久保护已确认** | 规划长期文明战争/退场机制前 |
| OPEN-02 | 本地离线文明包长期自治程度？ | 已确认真实离线对手源于其他玩家；可自主执行；完整战略能力未冻结 | 文明管理架构稳定前 |
| OPEN-03 | 核心区保底 E/M 配额和储量怎样定量？ | 极低速不可断、随时复建已确认；数值未确认 | 经济与首次全毁复建试玩阶段 |
| OPEN-04 | 核心区如何防止无限资源套利/永久围困？ | 不能把玩家卡死、不能破坏经济意义 | 核心区恢复玩法实现前 |
| OPEN-05 | “五分支最新产品”以哪种实物/数字状态保存？ | 必须保留产品，不能退化为纯口号 | 工坊版本化+保底恢复集成前 |
| OPEN-06 | 跨区入口形态、承载类型、运输时间与成本？ | 多区域，区内真实二维，连接明确 | 跨区仿真实现前 |
| OPEN-07 | 游戏 C 预算如何确定性计费、超限处理？ | 固定基础预算、硬件/协同升级；不按 CPU 毫秒 | JS 预算设计阶段 |
| OPEN-08 | 区域大小、具体地图坐标系统和离屏模拟精度？ | 多区域+统一持久世界 | 世界扩展与性能评估前 |
| OPEN-09 | 基质简化物流的用户可见粒度？ | 不允许免费跨区瞬移 | 资源 UI/物流实现前 |
| OPEN-10 | 文明外交/贸易具体范围？ | 允许合作、交易、战争等方向；不强制复杂模拟 | 文明长期玩法阶段 |
| OPEN-11 | 多终局有哪些、是否互斥、奖励/世界变化？ | 多路径且终局后继续沙盒 | 正式战役和叙事实施前 |
| OPEN-12 | 研究/构造认证/高级编程有哪些技术依赖？ | 基础探索研究，高级构造与编程 | 全科技成长内容制作前 |
| OPEN-13 | Godot 图形细节、镜头透视、装配几何？ | 精致 2D/Blender 预渲染/Shader 方向 | 美术垂直切片前 |
| OPEN-14 | 最低配置、最大设备规模、固定 Tick 频率？ | 20 Tick/s 是候选，不是批准值 | 基准/性能验证后 |
| OPEN-15 | Steam Workshop 是否纳入首发？ | 可选内容传播，不能依赖开发者服务器 | 首发范围锁定前 |
| OPEN-16 | 原主控是什么、它为何崩溃？ | 只确定崩溃已久、文明已成熟 | 世界观扩写与终局叙事前 |
| OPEN-17 | 核心区与已部署高级五分支的具体复制成本？ | 需保留最新产品且保底能复建 | 经济防套利设计前 |

## 不能自动写死的示例数值

`20 Tick/s`（候选）、`1 E/s`、`0.2 M/s`、`300 E`、`100 M`（示例）、`10/100/300/500/1000` 控制器（压测负载）与第一次正式战斗 `30–60 分钟`（体验目标）。仅“30–60 分钟首战”属于之前已批准方向；其能否达成需试玩。

```md
实验/试玩/截图与数据：
推荐方案与推荐理由：
是否影响已确认决策：
需要用户确认的精确问题：
回滚与迁移方案：
```

对确实会更改已确认事项的 ADR，应提交用户确认，而不能只因 Agent 自己的推理就修改产品承诺。
