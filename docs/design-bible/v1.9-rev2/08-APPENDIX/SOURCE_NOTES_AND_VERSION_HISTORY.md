# 设计来源、版本演变与可信度说明

## 重要声明

本档案汇总用户截至 2026-11-16 对话中已明确给出的产品方向、V1.9 Rev1、V1.9 Rev2 决策，以及此前 V1.5/M0 记录中未被推翻的共识。**不是对全部历史版本逐字检索后形成的“用户确认过每一条细节”的证明。** 所有未能直接确认的设计已尽量用 `[PROPOSED]/[OPEN]` 标注。

## 源头与演进（高层）

1. **最早创意**：受工程/编程游戏启发，设想一片可编程二维数字世界；大量几何化个体遵守简单规则，在真实资源、通信与局部感知约束下产生自主协作、对抗和涌现行为。重点不是生物繁殖、遗传或意识模拟。
2. **V1.5 共识**：实时指挥+暂停+自主程序；模板+真实编程；精致模块化机架；首战 30–60 分钟目标；手工关键体验+半程序区域；轻剧情；单机离线包；精致 2D+Blender+Shader。早期技术运行时曾讨论 Lua/Luau，后被替换。
3. **V1.9 / Rev1**：五个最低可用分支完成后即可进入 PvE；高级 AND/OR 仅管理进阶构造；动态世界、真实机会提示、统一工坊/关卡/存档规则；工坊和代码编辑默认暂停但可实时。技术明确为 Godot 4.7.2 .NET + C# + JavaScript/Jint 4.18.0。
4. **V1.9 Rev2 八项选择**：Q1=B（多区域）；Q2=B（可恢复存续，随后由核心区规则具体化）；Q3=C（能源网络+基质简化物流）；Q4=C（基础 C + 硬件/分布式升级）；Q5=B（协议/偏好/资源形成文明差异）；Q6=B（主控崩溃已久，成熟文明）；Q7=C（多终局，后续继续沙盒）；Q8=C（探索/研究+构造验证+编程）。
5. **Rev2 最新补充**：不可摧毁玩家种子核心区，永久保存原始种子与五分支最新已确认架构的产品；保底 E/M 极低速且不可切断再生，外部全毁仍可复建。PvE 对手由其他玩家**离线版本**构成，在本地运行；不运营开发者服务器。

## 与旧文件冲突时

- 旧文件称 Godot Standard、Lua/Luau 作为首发语言 → **无效**，以 Godot .NET/C#/Jint 为准。
- 旧文件称核心彻底失效导致玩家死亡 → **无效**，以不可摧毁核心区/永远可复建为准。
- 旧文件只做单区域 → 那是 M0 的**实验范围**，不是完整游戏架构；完整产品为多区域。
- 旧文件暂缓多文明/跨区/终局 → 那是当时 M0 的**任务范围约束**，不是游戏最终不会有这些系统。
- “内置对手”不与“其他玩家离线文明”为核心相冲突：开发者可用玩家同款工具制作内置文明版本。
- “技术建议”与“用户已确认规则”必须区分，未做出的选择不得由 Agent 默默补完。
