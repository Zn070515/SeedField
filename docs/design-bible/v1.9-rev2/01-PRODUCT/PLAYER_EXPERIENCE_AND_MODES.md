# 玩家体验、模式与节奏

## 主要玩家操作层级

**观察层**：查看区域、设备、供电拓扑、可见目标、通信状态、库存和事件；不知道的敌情不得被上帝视角 UI 免费透露给程序或玩家控制系统。[BASELINE]

**设计层**：工坊装配元件 → 形成蓝图/模块/产品 → 在测试场景验证 → 决定部署/升级；JS 编辑器定义控制行为，支持诊断与回退。[CONFIRMED 方向]

**指挥层**：玩家给区域、单体、编队或系统下达任务，不以持续拖拽微操取代程序；任务和程序升级仍服从通信与部署条件。[BASELINE]

**战略层**：选择探索路线、资源节点、区域连接、设施位置、自动化/战争投入、外交/对抗立场、文明终局路线。[CONFIRMED 方向]

## 模式之间的关系

| 入口 | 玩家目的 | 数据与规则 |
|---|---|---|
| 五分支入门教程 | 获得最低可工作的系统 | 同元件库/统一规则；完成立即开放 PvE |
| 构造挑战 | 学会/验证特定组合与功能 | 可用 AND/OR 前置解锁**后续能力**，不得阻止已开放自由世界 |
| 自由世界 | 建设、探索、进化、竞争 | 核心主模式：多区域、持久世界和离线文明 |
| 工坊/程序编辑 | 设计、调试、封装 | 默认暂停，可手动切换实时；设计版与已部署实例分离 |
| 训练/竞技场 | 无生产代价测试程序与装配 | **PROPOSED**：无战役损失、同样仿真核心、可固定种子重放 |
| 回放/实验室 | 比对战术、观测诊断 | **PROPOSED**：仿真事件回放，不允许重放特效成为真实状态源 |

## 首次体验的承诺

前期强调基础建设与构造，但 **30–60 分钟经历第一次正式战斗**是既有产品节奏目标，并非等待所有高阶知识才能进入战斗。编程可以是这场战斗的增强手段，但不是必过的考试。

一个建议的首次体验顺序 [PROPOSED]：

- 进入种子核心区，看见五分支失活或最低状态。
- 分别完成能源→感知→通信→状态→执行五类最小结构（实际教学顺序可依试玩调整）。
- 进入第一个真实世界区域，找到可利用资源，部署最低可用设备。
- 一次可理解的侦察/资源/中继站冲突，引导第一次攻防。
- 提供程序模板，让喜欢编程的玩家主动修改；非程序玩家先通过简化控制完成基础防御。

## 玩家失败与容错

- 核心区不毁坏、保底 E/M 不可切断，因此不出现不可继续的死亡存档。[CONFIRMED]
- 外部战败有代价，设施/军队/库存可以失去。[CONFIRMED]
- 提供故障快照、失败原因、最近一次成功部署和版本回滚是**建议交互工具**，不是自动替玩家赢。[PROPOSED]

## 长期动机

1. **能力**：解锁更多可构造的元件、架构和策略维度。
2. **效率**：节省能源、基质、带宽、算力或时间。
3. **鲁棒性**：在断联、资源短缺、攻击和故障下继续运作。
4. **规模**：多个区域、更多设备、更复杂的协作。
5. **对抗**：挑战不同玩家离线文明的工程思路。
6. **探索与终局**：实现自己的文明尺度目标并继续建设。[CONFIRMED 终局后延续]

## 节奏与复杂度限制 [PROPOSED]

- 玩家必须能快速用模板/默认策略做出有用设备；深入编程是自选高收益路线。
- 不以几十种早期原料、完整机械装配或过度 GUI 复杂度锁定入门。
- 每出现一种新资源或容量约束，UI 必须给出来源、消费方、瓶颈和改进方式。
- 多文明战争应从小规模交战逐渐扩展，避免早期满屏战争使设计玩法失焦。
