# SEED FIELD《种子域》— 全游戏设计总档案

> **版本：V1.9 Rev2（综合基线）** · 整理日期：2026-11-16 · 交付对象：Coding Agent、设计 Agent、技术美术 Agent、项目负责人  
> **范围：整个计划中的商业正式游戏（Full Game），不是 M0 阶段，也不是现成可运行的源代码。**

## 用一句话理解本作

在一个中央主控崩溃已久的二维数字世界中，玩家通过元件构造、JavaScript 编程、能源与物资网络和自主设备，逐步建立可持续运行的数字文明，并与其他玩家留下的**离线文明版本**在本地世界中探索、合作与竞争。

## 绝对前提

1. Windows 优先，Steam 付费单机；**完整游戏无需网络、账号、开发者服务器**。其他玩家的文明以可移植离线包形式存在，导入后在本地运行；正式版必须有可完整游玩的内置对手。
2. **Godot 4.7.2 .NET（.NET 10.0 构建目标）+ C# 统一仿真 + JavaScript/Jint 4.18.0**；编辑器类型提示采用 TypeScript `.d.ts`，不等于运行 TypeScript 源码。
3. 五基础分支为**能源、感知、通信、状态、执行**。新手教程只要求每类最低可用结构，完成后立即允许进入 PvE；效率和复杂程度不得作为准入门槛。
4. 世界是**多个相互连接的区域**；每区仍是可导航的真实二维空间。各区属于同一持久世界，使用一致的世界规则。
5. 玩家拥有**不可摧毁的种子核心区**：永久保存种子及五分支最新已确认架构的产品，极低速、不可切断地再生基础 E/M，始终允许从零复建。外部基地/资源/军队可失去。
6. 游戏本质是**程序化的系统创造与自主涌现**，不是生物繁殖/遗传/意识模拟，不是纯图论网络可视化，也不以线性剧情或微操战斗取代工程玩法。

## 重要：状态标签

- **[CONFIRMED]** 用户明确选择或此前已经明确冻结的方向。Agent 不得擅自推翻。
- **[BASELINE]** 从较早讨论延续、尚未被明确推翻的设计共识。后续文档冲突时以更晚确认内容为准。
- **[PROPOSED]** 为使设计可实现提出的规则、数据结构、参数或示例。**不等于用户已确认**。
- **[VALIDATE]** 需要在实际原型、性能测试、视觉样片或真人试玩中确定。
- **[OPEN]** 尚未形成产品决定；严禁将建议写成既成事实。

`00-START-HERE/DECISION_REGISTER.md` 为版本决策主索引。所有跨文档冲突必须登记到 `08-APPENDIX/OPEN_QUESTIONS_AND_ADRS.md`，不得悄悄选一个。

## 给 Agent 的入口

先读 `AGENTS.md` → `GOAL.md` → `00-START-HERE/DECISION_REGISTER.md` → `07-AGENT/MASTER_HANDOFF.md`。完成阅读后输出：理解摘要、确认规则、待验证事项、受影响模块、首批任务及可复现验收方式；随后开展实现。**不得把档案中的全游戏愿景理解为要求一次性把所有功能写完。**
