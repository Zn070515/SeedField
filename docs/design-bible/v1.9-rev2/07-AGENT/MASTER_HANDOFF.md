# MASTER HANDOFF — 交给 Coding Agent 的总交接指令

> 可直接把本文件与整个 ZIP 放入 Agent 的项目上下文。**这是一份全游戏目标与开发规范，不是要求在一次执行中完成所有功能。**

## 角色与首要任务

你将协助实现 Steam 单机游戏《种子域》（Seed Field）。以本资料包中的 **V1.9 Rev2 综合决策**为产品基线，先熟悉设计，不得凭个人熟悉度将游戏改写成普通 RTS、纯逻辑沙盒、联网 MMO 或生物进化模拟。

**你的第一项工作**不是创建几十个类或美术占位，而是：

1. 检查现有仓库/工程/工具链/版本和已运行的测试；如果仓库没有现成工程，再提议最小工程骨架。
2. 阅读 `AGENTS.md`、`GOAL.md`、`00-START-HERE/DECISION_REGISTER.md`、全部 `03-GAMEPLAY/` 和 `04-TECH/` 相关契约。
3. 输出 `IMPLEMENTATION_BASELINE.md`：已确认规则、现有代码真实状态、需验证的 API、未决选择、风险、推荐首个可运行切片。
4. 输出按 `06-PRODUCTION/FULL_GAME_ROADMAP.md` 分阶段的任务 DAG/依赖/验收；不要把所有工作硬塞进 M0。
5. 开始首个**可运行、可复现、可截图**的纵向小场景验证，提交源码+测试+日志+截图，而不是只有 TODO 清单。

## 绝不能遗漏的设计核心

- 真实二维世界组织为**多个互连区域**，不等于独立关卡。
- 中央主控崩溃已久；弱小玩家种子进入成熟文明世界。
- 五分支：能源、感知、通信、状态、执行；最低可用全部完成即开放 PvE。
- 高阶构造挑战 AND/OR 只能限制高阶能力，不能阻塞基础 PvE。
- 工坊设计与世界部署实例分离；暂停默认、实时可选。
- 设备由自主程序行动，玩家实时下达战略任务；同源资源/信息/计算规则。
- 技术：Godot 4.7.2 .NET（.NET 10.0 构建目标），C# SimulationCore，JavaScript/Jint 4.18.0，TypeScript `.d.ts`。
- E 能源、M 基质是库存；C 算力、S 存储、B 带宽为分布式能力。
- 核心区永不被毁、永久保留种子与五分支最新已确认架构的产品、低速不可切断再生 E/M，外部全毁仍可复建。
- PvE 对手设计来自其他玩家的**离线文明版本**，本地自主运行；必须有丰富的内置包，不依赖自家服务器。
- 多种文明级终局，完成后继续沙盒；轻剧情与精致 2D、美术品质为产品要求。

## 已定与未定

**已定原则**不得随意重议。**尚未确认**：其他文明核心区能否永久不灭；跨区入口与物流具体费用；核心区保底配额数值/防套利/围困；C 的确定性计费与超预算行为；长期完整文明包的战略能力范围；详细终局和科技树；最低配性能目标。

未定项可在小场景使用可配置假设并写 ADR，不得把它们说成用户批准。实施过程中优先收集数据与可体验样片。

## 技术防线

- `WorldState → Observation → Controller → Intent → SimulationCore → Events` 是统一逻辑。
- 所有第三方 JS 不可信；Jint 运行限制**不等于**操作系统安全沙盒。
- 不能开放任意导入玩家 JS 后直接在游戏进程执行，直到有 OS 级隔离+IPC 验证。
- 绝不要求自有游戏服务器、账号、实时同步或云推理。
- 不让未知敌方信息透过 UI/程序/AI 路径泄漏，不使用敌方作弊资源。
- 不让两个 Agent 自己定义两套不同消息、Tick 或资源语义。
