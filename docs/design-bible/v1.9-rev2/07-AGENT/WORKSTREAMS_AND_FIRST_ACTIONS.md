# Agent 工作线、依赖关系与首轮动作

## 长期工作线 [PROPOSED]

| 工作线 | 主要负责 | 禁止事项 |
|---|---|---|
| 规则与架构 | 唯一 C# 仿真接口、schema、Tick、资源事件、迁移 | 不能把业务逻辑塞进视效或另一套脚本状态 |
| 构造与成长 | 五分支、工坊、模块、科技/关卡、版本化部署 | 不得把所有高阶能力锁在 PvE 入口前 |
| 脚本与诊断 | Jint 4.18、JS API、计算预算、沙盒、编辑器 | 不得让 JS 持有可变世界对象/CLR 任意权限 |
| 世界与文明 | 多区域、跨区连接、存档、离线对手、终局 | 不得发明开发者后台或 NPC 透视作弊 |
| 视觉与 UI | 艺术规范、Blender/Godot 资产、叠层、可用性 | 不得用概念图冒充运行截图 |
| 质量与安全 | Headless、对战测试、故障注入、benchmark、安全导入 | 不得只报告 CI 通过而无真实性能/可玩证据 |

## 推荐的首轮执行步骤

1. **环境与事实审计**：读取仓库及各配置（Godot `.csproj`、NuGet、CI、测试）；打印真实 SDK/版本及可编译状态。没有仓库时不要假设之前的 M0 starter 已经可运行。
2. **单一合同**：建立/核对 `World/Region/Entity/Observation/Intent/Event` 最小 Schema，并为权限、资源、消息时序写失败测试。
3. **C# Headless 小场景**：用可复现规则让两设备对抗，验证 E/M、局部感知、通信延迟、单武器。
4. **Jint 4.18.0 编译实测**：最小 JS 回调、状态、超限故障与运行规模基准，记录准确 API 兼容性。
5. **Godot 可视**：从同一世界事件画出真实机体/信号链/命中，不引入第二套仿真逻辑。
6. **核心区最小保证**：验证外部设备/库存全部清零后，永久种子+五分支保底可复建最低设备。
7. **交互验证**：让玩家编辑一个程序/蓝图，部署到世界，再观测代码变化的行为差异与故障原因。

```text
  ├── JS Runtime Spike ──────────┘

美术管线样片 ────────────────────> 商业可玩切片/正式资源
安全隔离 ───────────────────────> 开放第三方 JS 执行闸门
```

## 第一批建议文件（若仓库不存在）

可从 `GOAL.md`、`AGENTS.md`、统一决策登记、`SimulationCore` 最小 schema、真正可运行的 Godot .NET 工程、`tests`、`benchmarks`、`assets/sources` 开始。不要为了对应本包每一个章节就立即建立几十个空模块。

## 应该提交为用户审批的 ADR

- 其他文明是否绝对不可毁与本局退场政策；
- “最新五分支产品”在核心区的实物/设计权威与有限再生配额规则；
- 跨区通道类型、最低物流的交易/时间语义；
- C 游戏算力计费与超限后结果；
- 离线对手包是否包含完整长期战略自治；
- 多终局的具体机制与是否互斥。

可先在可配置接口后面做原型，但不得将演示参数冻结为商业规则。
