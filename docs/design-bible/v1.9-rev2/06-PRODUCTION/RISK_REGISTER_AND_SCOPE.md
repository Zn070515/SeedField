# 重大风险、范围控制与触发式应对

| 风险 | 影响 | 提前验证 | 触发后的应对 |
|---|---|---|---|
| Jint 执行成本与内存规模 | 大量控制器时卡顿 | 10/100/300/500/1000 控制器 benchmark | 优化调度/数据与热路径，阻断才评估替代引擎 ADR |
| 第三方 JS 不可信 | 恶意代码、崩溃、数据损坏 | OS 隔离、IPC fuzz、恶意输入测试 | 不开放社区执行，先用内置对手 |
| 多区域一致性复杂 | 物资瞬移、时间错乱、刷资源 | 确定性/加载与卸载/跨区队列回归 | 缩减区域规模，保持统一模拟契约 |
| 核心区无限资源套利 | 战略经济失衡 | 长时仿真、导出配额与围困测试 | 调整保底容量/使用边界，不取消复建保证 |
| “玩家文明包”不能长期自治 | PvE 不够自然 | 让内置包在不同世界条件下独立采集/防御 | 先做明确合法的战术/工业层，迭代战略层 |
| 复杂规则不易学 | 新玩家放弃 | 五分支真人教程、首战时间与错误反馈 | 降教程难度、加强模板/可视诊断，不能强制考 JS |
| 工作量无限增长 | 永远做不出商品 | 按里程碑验收和时间盒评估 | 先砍地图规模、文明数量、后期巨构/复杂外交 |
| 美术路线不可持续 | 成本巨大或视觉廉价 | 真实 Godot 样片、资产管线、缩放截图 | 调整 2D/Blender 分工，固定复用的资产规范 |
| 存档/蓝图兼容性 | 玩家进度丢失 | schema 版本、迁移和回退 | 加冻结兼容层，拒绝静默破坏 |
| 断网依赖意外渗入 | 与核心定位冲突 | 拔网全流程端到端 | 移除强制线上依赖，改为内置/本地文件 |

## 强制拒绝的“方便做法”

- 给对手文明开全图透视以弥补 AI 逻辑不足，却告诉玩家它遵守规则。
- 把场景暂停等同于 UI 暂停，但后台战斗继续推进。
- JS 直接调用 C# 的 `SetWorldState`，绕过合法意图验证。
- 通过日志里输出脚本错误但 UI 没有任何解释。
- 默认修改一个蓝图就瞬间修改所有外部世界设备。
- 把核心区资源设成零后要求玩家外出采矿才能恢复最低执行能力。
- 依赖自家服务自动下载更新离线文明，否则世界无法运行。
- 完全依赖其它真实玩家上传作品，内置内容只有一个模板。
- 因没有美术资源就把简单线框称作付费版“设计风格完成”。

## 范围分级 [PROPOSED]

**必须有**：五分支、真正 JS、装配与部署、有限信息、E/M/C/S/B 至少有意义的约束、能源/简化物流、至少基本多区域、核心区复建、内置离线对手、动态攻防、正式视觉、持续世界与至少一条可完成的终局路线。  
**应该有**：多组离线文明、可重放诊断、程序差异对比、更多建设路径、部分高级科技、可靠迁移和可访问性。  
**可以后来再有**：Workshop、复杂外交、多个巨型武器、联机、排行榜、多人共享世界、大规模叙事演出。  

注意：完整设计愿景最终期望**多种终局**，这里的“一条终局路线”仅指商业内测的最小纵向闭环，不能偷偷改成正式版只需一条而没有用户确认。
