# Steam 商业发行、离线体验与维护原则

## 商业边界 [CONFIRMED]

- Windows 首发优先，付费 Steam 单机。
- 无开发者托管的持续世界/匹配/账号/数据库/AI API 服务。服务器预算不足是**长期架构约束**，不做“先用服务后补单机”的倒置方案。
- Steam Workshop 可作为未来可选功能，不能成为 PvE 内容量或发布的前提。
- 全功能离线：新游戏、基础教程、内置对手、存档、终局、构造/编程/训练均无需网络。

## 正式版可交付定义 [PROPOSED]

- 真实可玩的全循环，而非只有概念、IDE 或测试地图。
- 完整的首次体验和难度曲线；非程序玩家进入游戏，程序玩家有充分深度。
- 足量风格不同的内置离线文明/战略行为，避免社区零内容时世界空荡。
- 明确的教程、错误诊断、程序/蓝图版本管理。
- 多个区域、工业/通信/战斗网络、有意义的研究与多文明终局。
- 发生重大失败后仍可用核心区复建，并有可用的恢复 UI。
- 正式 Godot 美术、声音、可读信息叠层、基本图形设置。
- 安全、崩溃恢复、存档迁移与旧版本回归。

## Steam 准备工作 [PROPOSED]

- 游戏名称、logo、胶囊图、截图、预告片和特色说明的版权/来源审查。
- Windows 桌面构建、下载包大小、安装/卸载、保存目录、离线启动、控制器/键鼠（如果支持）、分辨率/字体。
- 商店页面如实描述：单机、编程语言、是否包含/支持社区离线文明包、是否需要 Steam 网络才能获取新增作品。
- 发行前持续收集试玩录屏，验证用户是否理解产品卖点与首小时节奏。
- 平衡评分、最低配置、目标价格和发行窗口通过真实 benchmark/市场调研确定，不在此文档凭空承诺。

## 维护与未来选择

- 可通过本地文件的文明包导入/导出作为低成本传播途径。
- 安全完成前**不开放可执行未知第三方 JS**；可以先发布内置作品与纯数据验证。
- 可选 UGC/Workshop、更多文明、丰富外交和巨构属于后续扩展，并非“缺了就不是完整游戏”。

## 法律与可信赖运营提示 [PROPOSED]

软件、音效、美术、第三方库许可证与署名要可追溯；导入他人作品需要版权/来源提示；对玩家文件与存档遵守最小访问原则。具体 Steamworks 接入、商店规则和平台费用须在执行时参考最新官方要求核实，不把本文件当作永不过期法规。
