# 《种子域》完整开发路线图（不是单阶段方案）

> 这是**从零到正式付费产品、发布与维护**的建议路线图。除主要技术栈和已确认玩法外，阶段划分、排期、内容量、实体数目标属于项目管理建议 `[PROPOSED]`，不得误读为已获用户确认。**不规定未经验证的上线日期**。

## 总体阶段

| 关卡 | 阶段名称 | 产品形态 | 退出证据 |
|---|---|---|---|
| **M0** | 技术与核心手感可行性 | 小规模可运行原型 | 真 JS 驱动单位；同规则仿真；安全/视觉基础验证 |
| **M1** | 五分支与工坊闭环 | 可玩系统沙盒切片 | 五最低可用、设计/制造/部署/版本化升级 |
| **M2** | 基础经济与自治网络 | 第一套可优化系统 | E/M/C/S/B 核心约束、断供/断联/物流、调试闭环 |
| **M3** | 多区域与种子存续 | 持续世界雏形 | 区域迁移、跨区事件、保底复建、存档回归 |
| **M4** | 模块化战斗与离线 PvE | 可玩的攻防游戏 | 战构体/战术、内置离线对手、第一场正式攻防 |
| **M5** | 文明成长与长时沙盒 | 多文明长期玩法 | 研究/构造、工业扩张、多个离线文明长期行为 |
| **M6** | 内容与视觉纵深 | 可销售的完整 Beta | 正式美术、主要区域/敌人/任务/探索内容与 UI |
| **M7** | 终局、稳定性与 Steam 发布 | 候选商业正式版 | 多终局、存档兼容、性能/QA/商店/无网全流程 |
| **M8** | 发布后维护与可选社区生态 | 迭代升级 | 反馈修复、内容更新、可选文件分享/Workshop |

**禁止从路线图理解为必须严格单线程推进。** 美术样片、测试、安全、存档设计从 M0 就并行逐步成熟；阶段关卡只是清晰验收点。

## M0 — 技术风险前置

**目标**：证明 C# 固定 Tick + Godot .NET + Jint 4.18.0 能形成真实系统反馈，且最小美术方向成立。

**建议范围**：1 小区域、1–2 台己方设备、1 内置受控敌手、2–3 个设施节点、一种武器/护盾、能源与通信链路、最小观察/移动/开火/发信、基本的恢复概念。视觉真实 Godot 截图，不拿概念图验收。

**退出**：可编译运行；固定种子同结果；脚本死循环/越权不能拖坏状态；程序改动可见战术差异；有实际机体/网络/战斗样片、已记录安全不足。[VALIDATE]

## M1 — 玩家五分支与可构造设备

**目标**：证明非程序员也能构造最低设备，理解组件的互连关系，并自然过渡到代码。

**交付**：五分支元件和最低功能验证、构造工坊、封装/蓝图版本、第一组构造挑战、最小可用教程、已部署实例和主动更新机制。

**退出**：五分支最低可用完成即可解锁自由 PvE；低效率不会被拒；工坊设计不自动覆写外部实例；AND/OR 进阶挑战不限制主游戏。

## M2 — 真正需要优化的能源、物料、信息与计算

**目标**：把系统真正连接起来，使“能量、材料、算力、状态和带宽”的约束会改变玩法。

**交付**：供能/储能/负载、M 的地点与简化运输、有限传感器、B/S/C 约束、断联自治、JS 预算与程序调试、工坊/编辑器默认暂停与实时切换。

**退出**：可解释的故障与瓶颈出现；同资源下不同代码有显著效果；资源与信息守恒、恢复/重放测试通过。

## M3 — 多区域、核心区和可持续世界

**目标**：从一个封闭关卡过渡为持久区域网络，有合法跨区因果和永不失去恢复起点的玩法。

**交付**：区域索引/连接、跨区移动/通信/能源/简化物流、离屏区模拟/加载、全局事件与存档、永久种子核心区、最新五分支产品保留与保底 E/M、从全毁中复建。

**退出**：远端资源不瞬移；断供、迁移、卸载/重载不破坏仿真；外部全毁能在有限步骤恢复；不存在核心区永久软锁。

## M4 — 战构体、攻防和离线文明战术

**目标**：让代码/设备设计决定战斗胜负而不是纯数值；实现首场正式战斗的可玩产品节奏。

**交付**：模块化机架、真实武器/护盾/驱动/传感器、伤害/模块失效、战术任务与控制、内置离线对手、基础战斗任务、可解释攻防回放。

**退出**：真实玩家 30–60 分钟能遇到第一场正式攻防；不同程序/装配带来显著策略效果；对手不作弊、不要求服务器。

## M5 — 文明长期运行与成长

**目标**：让世界具备自主变化的资源、文明和战略节奏，而不是一连串静态防守关卡。

**交付**：成熟文明背景与初始势力、持续建设/采集/扩张、科技探索/研究+构造验证、文明发展偏好、区域争夺与初步外交、多个不同风格的内置离线文明。

**退出**：玩家不主动触发事件时世界仍有合法演化；长期无网可玩；敌我资源/信息约束一致；新手不会被成熟文明无解消灭。

## M6 — 美术、UX、内容和可销售完整度

**目标**：把“原型好玩”变成“商品完成度足够”的正式游戏体验。

**交付**：统一美术规范、所有关键模块的正式画面、声音反馈、足量区域/目标/遗迹/事件、教程与错误交互、存档/蓝图浏览、性能优化、可访问性。

**退出**：真实游戏截图可用于商店页面；缩放与密集战场可读；玩家能查出程序/供能/物流错误；主要玩法贯通，不再靠开发者解释。

## M7 — 多终局、发布验收与 Steam

**目标**：完整离线单机从开局到至少一条文明级终局可通关，达成后持续沙盒。产品能发行并长期维护。

**交付**：多种终局路线、终局持久世界变化、内置对手多样性、全局存档迁移、安全回归、正式 Windows 包、商店素材/说明/用户许可/成就和本地化方案（按成本决定）。

**退出**：断网、全新 Windows 环境、旧存档、不同难度、核心区复建、文明对战、终局后续玩均实际通过端到端验收；商店与发售检查通过。

## M8 — 发布后

修复崩溃/兼容与存档问题；新增区域、元件、挑战、离线文明；如果安全和成本可控，再评估对手包文件导入升级与 Steam Workshop。**不以发行后一定有社区规模为正式产品可玩性的前提。**

## 三条贯穿整个 Roadmap 的持续工作线

**工程质量**：CI + 单元测试 + Headless 回归 + 安全审计 + 存档迁移，不因阶段改变而临时补丁堆砌。  
**设计验证**：真人试玩、有效时长和操作瓶颈、系统涌现案例、失败复建的挫败/动力平衡。  
**艺术产品**：从第一批可运行样片起反复比较 Blender/2D/Shader 组合，不到 M6 才临时做完全部美术。

## 放弃功能比堆功能更重要

若资源不足，优先砍掉**文明数量、后期巨构、复杂外交、地图规模、特效数量、Workshop/联机**，不要砍掉：真实 JS 改变行为、五分支教程准入、核心区永不软锁、无服务器离线对手、统一世界规则和基本视觉完成度。
