# 区域世界结构与空间规则

## 已确认的空间选择 [CONFIRMED: Q1=B]

世界由**多个区域**构成，区域之间以明确的通道或网络连接。**每个区域内仍是真实的二维空间**：单位有坐标、方向、碰撞/射程等物理与战术意义；不是只有节点和边的抽象图。

世界具有统一时间、持久文明/资源/关系状态和全局可追踪事件。[BASELINE]

## 区域示例类型 [PROPOSED]

| 区域类型 | 主要用途 | 典型风险 |
|---|---|---|
| 种子核心区 | 永久存续、最低复建 | 部署出口被封锁的软锁风险 |
| 安全起步区 | 最初资源、基础工坊、首次防御 | 过低挑战或过快资源产出 |
| 能源带 | 能源采集/传输、节点控制 | 供电中断和负载瓶颈 |
| 旧通信枢纽 | 侦察、中继、协议发现 | 信息泄露与断联 |
| 工业遗迹区 | 探索、逆向、复杂构造 | 占领、维修和运输成本 |
| 文明边境 | 对手文明接触与竞争 | 情报不对称、远程后勤 |
| 高阶争夺区 | 多文明战略目标 | 路径争夺、资源消耗 |

这些名称仅为内容示例，不是正式世界地图。

## 推荐的三层空间模型 [PROPOSED]

1. `World`：全局整数 Tick、区域目录、文明索引、持续事件队列。
2. `Region`：区域二维网格/连续坐标、实体、局部物理与资源状态。
3. `Connection`：区域连接，分别声明 `units/material/energy/information` 可支持的传输类别及容量、成本、延迟。

> 一条物理通道不一定具备能源/数据/物资所有能力。不得默认点击跨区就立刻免费传送一切。

## 跨区行为的基本不变量

- 单位不能在未经连接验证时跨区瞬移。
- 物资库存有所在位置、归属与流转记录，**不能用全图共同库存无成本建造**。
- 通信传输必须考虑可达性和至少一个可解释的消息时序；本 Tick 发送的消息不应同 Tick 被远端“提前读取”。
- 跨区供能若允许，必须明确连接允许及容量/状态；外部网络被切断时能量不能凭空到达。
- 单一区域不在画面中时，世界如何推进仍需稳定的模拟策略，而不是彻底冻结导致文明行为失真。

## 后台模拟与扩展 [VALIDATE]

首发完整世界可以采用**活跃区细模拟 + 远端区粗模拟/事件模拟**，但远端更新必须与全局经济、战斗、通信的合法性一致。简化不能制造额外资源、提前交付消息或绕过资源/观察约束。需要可复现的加载/卸载测试。

## 未确认

- 出入口可否直接站立/通过，还是特定节点/门/航线。
- 地图是否固定格点、连续二维坐标或混合。
- 区域载入时的渐进式更新、模拟精度和规模上限。
- 时间/空间缩放、跨区运输载具、交通堵塞等具体机制。
