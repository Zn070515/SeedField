# AGENTS — 给所有开发 Agent 的硬约束

## 1. 先读后写

1. 阅读 `README.md`、`GOAL.md`、`00-START-HERE/DECISION_REGISTER.md`。
2. 阅读将修改的子系统规格和 `08-APPENDIX/OPEN_QUESTIONS_AND_ADRS.md`。
3. 检查现有代码、测试与实际运行状况；不可凭文件名假设已完成。
4. 在动手前列出实现范围、非目标、设计假设、测试证据；对未冻结条目明确标识。

## 2. 决策权

- `[CONFIRMED]` 不得擅自改变；如有技术阻断，先给出 ADR、实测证据、替代方案和兼容性影响，等待用户批准。
- `[PROPOSED]` 可以用作原型假设，但必须具备替换/配置能力，不能默认为商业最终规则。
- `[OPEN]` 禁止代替用户做不可逆的产品决定；允许做最小桩、可替换策略和独立实验。
- 当前唯一首发玩家编程语言为 **JavaScript + Jint 4.18.0**。不得因为个人偏好擅自替换成 Lua、Luau、Python、自研 DSL 或直接执行系统 Node.js。

## 3. 设计纪律

- **单一真实状态源**：C# SimulationCore 决定实体、能量、物流、命中、损伤、通信与跨区行为；表现层和脚本不能直接修改世界状态。
- **统一动作验证**：本地玩家、内置离线文明、导入对手包都通过 Observation/Intent/Validation 接口操作世界。
- **绝对单机可玩**：不接入必须在线才能运行的账户、遥测、匹配、经济或 AI 云推理服务。
- **不可摧毁核心区**：任何玩法都不得软锁玩家失去最低复建能力。
- **渐进式复杂度**：基础五分支只需最低可用；高级构造/编程是成长，不是入场门槛。
- **可复现**：统一 Tick/随机种子、稳定 ID/事件顺序；不以画面 FPS 或真实 CPU 毫秒决定仿真结算。
- **美术证据**：不能用概念海报或线框代替可运行的 Godot 机体、网络和战斗画面。

## 4. 不可信代码与数据

- 玩家/社区 JS 是不可信代码。Jint 进程内语句/时间/内存限制属于降级防护，**不能宣称足以隔离恶意对手包**。
- 在落实 OS 级进程隔离、最小权限、IPC 校验、资源限额和失败恢复前，第三方可执行程序包的自动导入/运行保持关闭。内置可信示例可用于早期验证。
- 禁止文件/网络/CLR/宿主对象访问；必须按白名单暴露纯数据、仅接受序列化意图。
- 包格式须版本化、限大小、检查路径穿越/压缩炸弹、控制脚本数量与源大小；未知 API 版本拒绝执行。

## 5. 交付证据

每批工作必须说明：改了什么、为何对应某条规则、如何构建、实际跑了哪些测试、得到哪些数值/截图、尚存的风险、是否影响其他模块。**CI 绿不代表游戏可玩，也不能把未执行的测试标成通过。**

## 6. 并行作业

- 仿真/规则只有一个权威 schema 与合并负责人，禁止多个 Agent 自建独立世界模型。
- 脚本 VM、技术美术、内容、测试可以基于冻结接口并行。
- 版本化数据格式变更须提供迁移测试，尤其是文明包、蓝图、存档。
- 需求越界需先出 ADR，不得为抢进度扩大首发范围。
