## 1. 范围与资产

要保护：

| 资产 | 说明 |
|---|---|
| 主机进程与用户文件 | 游戏进程、用户目录、存档、其他应用 |
| 世界状态完整性 | `WorldState`、存档、哈希与回放 |
| 玩家身份与网络 | 不要求在线，但包不得联网/外泄 |
| 游戏可用性 | 包不得让帧/内存/磁盘/CPU 被独占 |
| 其他包的隔离 | 一个包不能影响另一个包或内置对手 |
| 构建与分发链 | 包内容、签名、更新通道 |

不在范围（当前版本）：

- 已获得本机管理员权限的攻击者；
- 操作系统/CPU/驱动漏洞；
- 玩家自愿运行的恶意本地程序。

## 2. 信任边界

```text
[包作者 / 不可信文件]
        │  (JSON/JS/资源，未验证)
        ▼
[包存储 / 导入 UI] ──(schema/大小/哈希/签名)──► [允许清单]
        │
        ▼
[宿主进程] ──(只读 Observation + 预算)──► [工作进程：Jint]
        ▲                                      │
        └──────(Intent JSON，父进程重新验证)────┘

工作进程 -X-> 文件系统 / 网络 / 其他进程 / 宿主 CLR 对象
```

关键原则：

1. **父进程是唯一权威**：工作进程只能读过滤后的 `Observation`，提交 `Intent`；
   父进程仍执行全部意图归属、可见性、预算与状态校验。
2. **Jint 限制不是 OS 沙箱**：语句/内存/超时只降低风险，不提供进程/文件/网络隔离。
3. **默认拒绝**：未通过清单、哈希、签名、能力检查的包不加载。
4. **失败关闭**：工作进程超限/崩溃/协议错误 → 该包本局失效，世界继续运行。

## 4. 目标隔离架构（ADR-0020 方案）

### 4.1 进程模型

- **每个不可信包一个工作进程**（或每局一个，按性能测试决定；默认每包隔离更强）。
- 父进程持有 `WorldState`、RNG、Tick、存档；工作进程只收到：
  - 过滤后的设备 `Observation` JSON；
  - 当前 Tick、允许的 Intent schema 版本、CPU 预算；
  - 不包含其他文明私有状态、文件路径、主机对象。
- 工作进程输出：`Intent[]` JSON；父进程重新做归属/可见性/预算/状态校验。

### 4.2 OS 级限制（Windows 优先）

- 进程创建后立即加入 **Job Object**：
  - 内存上限、CPU 速率/时间上限、活动进程数 1、kill-on-job-close；
  - 超限由 OS 终止，不依赖包自觉。
- **受限令牌/低完整性/AppContainer**：
  - 无管理员、无网络能力（AppContainer 不授予 internetClient）；
  - 最小环境变量，不继承宿主句柄/管道以外对象。
- **文件系统**：
  - 包目录只读挂载/只读打开；工作目录为每包独立临时目录；
  - 禁止符号链接/硬链接/重解析点；路径规范化后必须在根内。
- **网络**：
  - AppContainer 无网络能力或防火墙按进程路径阻断；
  - 测试：包内尝试连接必须失败并记录审计事件。

### 4.3 IPC

- 命名管道/匿名管道，**长度前缀帧**，最大帧大小（例如 1 MiB），UTF-8 严格校验。
- 版本化消息：`hello`（包 ID/版本/哈希/能力）、`observe`、`intents`、`fault`、`shutdown`。
- 每条消息带请求 ID/Tick；父进程只接受当前 Tick 的响应，超时/乱序/重复丢弃。
- 未知字段/未知消息/非法枚举/超限数组 → 协议错误 → 终止该包。
- IPC 只传 Observation/Intent；不传文件路径、句柄、CLR 对象。

### 4.4 确定性与预算

- 工作进程不得使用真实时间/系统随机；游戏内随机由父进程通过 Observation 提供（若未来开放）。
- CPU 预算按 Tick 下发；超预算终止本 Tick 脚本（与 Jint 预算一致）。
- 回放时用相同种子/Observation 序列；父进程比对包输出哈希，分叉则标记包不可复现。

### 4.5 包格式与分发

- 包 = 签名清单 + 数据/JS 文件；不允许原生二进制/安装脚本。
- 清单：schema、包 ID、版本、引擎兼容、入口、能力、内容哈希、签名。
- 限额：总大小、文件数、单文件大小、解压比、路径长度、ID 长度。
- 签名验证失败/哈希不匹配/未知能力 → 拒绝加载。
- 离线优先：包是本地文件；不要求在线账号；Workshop 仅作为可选分发，不改变执行隔离。

### 4.6 生命周期与审计

- 加载前：清单/哈希/签名/能力/限额校验。
- 运行中：Job Object 限额、IPC 超时、Tick 预算、协议错误监控。
- 违规：终止工作进程 → 标记包 faulted → 本局不再调用；世界继续。
- 审计日志：包 ID/版本/哈希、加载/拒绝原因、预算使用、违规类型、退出码。
- 存档只记录包 ID/版本/哈希；不持久化工作进程内存。

## 5. 开放导入前的硬门禁

必须全部通过，缺一不可：

- [ ] 进程隔离 + Job Object/AppContainer 生效，且有自动化测试。
- [ ] 网络访问被 OS 拒绝（出站/入站/DNS）。
- [ ] 文件系统只读/空临时目录；路径穿越、符号链接、TOCTOU 测试通过。
- [ ] CPU/内存/磁盘/进程数限额测试通过；超限被强杀。
- [ ] IPC fuzz（超长/截断/乱序/重复/非法 UTF-8/未知字段）通过。
- [ ] Jint/原型链/构造器/宿主对象逃逸测试通过。
- [ ] 确定性回放测试：同种子/Observation → 同 Intent 哈希。
- [ ] 签名/哈希/允许清单/能力校验通过；失败即拒绝。
- [ ] 用户显式确认“未受信任包”及风险；不自动加载。
- [ ] 存档/回放在包缺失/版本不符时安全降级。
- [ ] 审计日志与崩溃/重启策略验证。
- [ ] 独立安全审查与发布检查清单。

## 7. 分阶段计划

- **Phase 0（当前）**：只运行内置 `builtin.*` 包；离线废墟只接受数据-only 快照；
  第三方导入关闭；仓库 Lint 守门。
- **Phase 1**：工作进程 + IPC + Job Object/AppContainer + 资源限额；
  仍只允许内置/白名单包。
- **Phase 2**：签名包 + 显式用户授权 + 本地文件分发；Workshop 可选。
- **Phase 3**：更难隔离场景（多包并发、跨平台 Linux/Steam Deck）与红队测试。

## 8. 待决问题

- 工作进程粒度：每包 / 每文明 / 每局？性能与隔离强度的权衡。
- 签名方案与密钥管理（开发者密钥、社区密钥、无签名但哈希白名单）。
- 确定性 CPU 预算：用语句/操作计数还是 CPU 时间；后者天然不确定。
- 包缺失/版本不符时的存档语义：拒绝读档、空控制器、还是回退内置对手。
- 用户授权 UX：首次加载警告、每包信任、系统级隔离提示。
- 跨平台：Windows Job Object 之外，Linux cgroups/seccomp、macOS sandbox 的优先级。
