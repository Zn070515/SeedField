# ADR-0003：E/C/S/B 原型语义

- 状态：**Accepted（仅限原型，不是冻结平衡）**
- 日期：2026-11-16
- 关联决策：E-01、E-02、E-03、E-04

## 背景

设计基线要求 E/M 是库存，C/S/B 首先是能力与容量；要求区分游戏算力与 Jint 宿主防护配额。当前实现需要一个可测试、可解释的最小模型，但不能把这些近似误当成已批准规则。

## 决定

| 标记 | 当前原型语义 |
|---|---|
| E | 实体本地电池 + 区域/文明电网库存；`SendEnergyIntent` 显式存入或运输，`DrawEnergyIntent` 抽取；无自动潮流 |
| M | 区域/文明本地库存；部署扣 M；跨区运输有在途与延迟 |
| C | 每条非 `Wait` 意图扣 1，受 `StateModule.ComputePerTick` 限制；不是 JS 语句/操作计费 |
| S | 己方所有 `StateModule.StorageCapacity` 之和作为收件箱容量；没有程序/历史存储模型 |
| B | 每实体发信上限 + 每链路消息/物资/能源批次上限；没有拥塞/优先级模型 |

- 所有数值均来自场景配置，不是平衡结论。
- UI/诊断必须显示实际扣费来源；不能只显示“资源不足”。
- 这些语义替换必须走新 ADR 与迁移，不得在内容中静默改口径。

## 后果

- 可以验证“资源约束会改变玩法”的最小闭环。
- 不能据此推断正式 C/S/B 计费、电网潮流、断供传播或跨区拥塞。
- 后续 M2/M3 需要在真实负载和试玩后重新评估，并更新决策登记。
