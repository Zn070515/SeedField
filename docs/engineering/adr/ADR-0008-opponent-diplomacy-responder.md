# ADR-0008：对手外交响应策略（原型）

- 状态：**Accepted（原型语义）**
- 日期：2026-11-17
- 关联决策：D-01、D-02、O-01、OPEN-10
- 前置：ADR-0007
- 后续：ADR-0009（主动提议与多轮反提议）

## 背景

ADR-0007 把签约、响应、接单限定为宿主命令，但没有回答“B 方由谁响应”。当前 Godot 面板只操作 A，A 发起的提议/贸易单会一直等待或到期。本轮由用户要求实现 B 方自动外交，范围为**响应 A 的待处理条目**。

## 决定

### 1. 形态

- 新增宿主侧 `OpponentDiplomacyPolicy`：纯函数，输入世界状态、双方文明 ID、通信路径与画像，输出 `DiplomacyCommand` 列表。
- 策略不修改 `WorldState`，不持有随机数、计时器或隐藏状态；命令由 `Main`/Headless 交给 `ExecuteDiplomacyCommand`。
- 只处理 **incoming** 条目（`TargetCivilizationId` 是本方），只响应指定对手；按稳定 ID 顺序返回。

### 2. 决策规则

1. 无通信路径：不响应。
2. 条约提议：
   - NAP：`AcceptsNonAggression` 决定接受/拒绝。
   - Trade：`AcceptsTradeAgreement` 决定接受/拒绝。
3. 贸易单：
   - 无生效 Trade 条约：拒绝。
   - 本区域库存不足以支付 `WantMaterial`/`WantEnergy`：拒绝。
   - 否则比较价值：
     `receivedValue * 100 >= paidValue * MinimumTradeValuePercent` 接受，否则拒绝。
   - 原型价值权重 M=1、E=1，由画像配置；不是正式平衡。

### 3. 画像

| 画像 | NAP | Trade 条约 | 贸易单阈值 |
|---|---|---|---|
| `builtin.skirmisher` | 拒绝 | 接受 | ≥120% 收益 |
| `builtin.turtle` | 接受 | 接受 | ≥100% |
| 未知包/默认 | 接受 | 接受 | ≥100% |

- 画像按对手包 ID 选择；不新增存档字段，读档后由包 ID 重建。
- 第三方包自定义画像需要包 schema 扩展，另行 ADR。

### 4. 接入

- Godot `Main.StepOnce` 在 `_engine.Step` 后运行策略；每个返回命令立即执行，事件写入现有事件日志。
- 面板打开时游戏暂停，B 在下一次 Tick 响应；不改变暂停语义。
- 事件日志新增条约/贸易事件的描述与颜色，便于玩家理解 B 的响应。
- Headless 新增 `--diplomacy-ai` 演示，不改变核心规则。

## 非目标

- B 主动提议、主动下单、多轮讨价还价。
- 信誉、记忆、威胁评估、人格对话、情报推理。
- 第三方包自定义外交画像。
- 隐藏信息：策略只读取与 B 相关的条约/提议/贸易单与区域库存。

## 后果

- A 的提议/贸易单会得到确定、可复现的响应，面板与玩法闭环可用。
- 策略是原型画像，不是最终 AI；不同内置对手有可区分的态度。
- 因为策略在 Tick 后运行，玩家在暂停面板中看到的是自己提交后的待处理状态，恢复运行后才看到 B 的响应。
