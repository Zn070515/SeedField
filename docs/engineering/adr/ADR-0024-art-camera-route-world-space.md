# ADR-0024：美术相机路线 A 与世界空间样片

- 状态：**Accepted（样片阶段）**
- 日期：2026-11-17
- 关联决策：ART-01、ART-02、ART-03
- 前置：ADR-0023

## 背景

Gate 1 用同一套三件 Blender 资产（电力设施、种子核心、模块工体）比较了
A 斜俯视 35° 与 B 严格俯视 90°。两条路线都有真实 Godot 截图、方向帧成本与
透明通道数据。

外部审查结论与本轮观测一致：

- A 能读出机械立面、模块高度与材质，适合“玩家建造的精密工业设备”；
- B 装配关系与占地轮廓更直接，但电力与核心容易都变成同心圆；
- 当前真正落后的是环境、镜头尺度、接触阴影与设备之间的视觉关系，而不是
  是否继续批量增加建筑。

同时发现 `StyleTest` 原先只是屏幕空间缩放贴图，地形/世界坐标/UI 不随
`Camera2D` 变化，不能代表真实游戏镜头；接触阴影是固定的大圆，设备像浮在
黑洞上；`art/blender/__pycache__` 被误提交。

## 决定

### 1. 路线选择

Gate 2 以 **A 斜俯视 35°** 为主要推进方向，B 资产与截图保留作为对照证据。
这不是正式美术验收；`status` 仍为 `style-test-not-final`。若后续实机可读性
或制作成本不达标，可回到 ADR 重新比选。

### 2. 世界空间优先

`StyleTest` 改为：

- 固定世界尺寸 2400×1500；地形、设施、网络、选中环全部使用世界坐标；
- 一个真实 `Camera2D`，远/中/近对应 0.62×/1.00×/1.65×；
- HUD 放在独立 `CanvasLayer`，不随相机缩放；
- 默认视图隐藏射程圈/敌情；`tactical` 与 `debug` 才显示；
- 所有 HUD 数字明确标注 `DEMO DATA` / `NO WORLDSTATE`。

### 3. 精灵锚点与接触阴影

- 斜俯视 pivot = 正面帧 alpha 包围盒底边中心（X 固定 0.5）；
- 严格俯视 pivot = 画布中心，便于旋转；
- 接触阴影改为沿主光反方向的椭圆，分两层软边；大型设施在阴影下再画
  八边形基座，明确“落地”；
- 地形色调限制在冷灰蓝，不再逐通道随机导致绿/紫色板块。

### 4. 轮廓分化

- 种子核心改为低矮、开放的**五折 cradle**：宽基座、五根内倾支撑、开放护环、
  悬浮暖色种子；不再是与电力塔同构的“更高的塔”；
- 模块工体改为不对称履带机架：前右挖掘臂、后左传感桅杆、背部空模块插槽；
- 电力塔保持用户认可的版本，不再改形。

### 5. 资产契约与门禁

`Art/manifest.json` 升到 schemaVersion 2，并在 `ArtAssetTests` 中强制：

- 每个 PNG 解码 RGBA，验证非空 alpha、覆盖率 4%–80%、四周留边；
- `alphaBBox` 与像素实际包围盒一致；
- 斜俯视 pivot 与正面帧 alpha 底边一致；俯视 pivot 为 0.5/0.5；
- 方向帧数量、角度、文件名完整；
- SHA-256、尺寸、路径、未登记 PNG 继续校验；
- `RepositoryHygieneTests` 禁止跟踪 `__pycache__/`、`*.pyc`、`*.pyo`。

`tools/build_art_manifest.py` 从运行时 PNG 与固定的 source/license 重新生成清单，避免手工
抄哈希/锚点。

## 非目标

- 不把样片标记为正式游戏美术，不改 SimulationCore、存档 schema、Jint、
  离线包安全契约。
- 本轮不做 8/16 方向图集、法线/发光 mask、核心四态动画、真实 `Main` 集成。
- 不把 Flux 概念图当运行时资产；不引入付费插件。
- 不声称已测最低配置 FPS/显存。

## 后果

- 远/中/近截图现在能代表真实相机缩放与遮挡关系。
- 斜俯视多方向资产成本仍在：电力/工体各 4 方向，核心 2 方向；后续移动单位
  需要先验证 4/8/16 方向收益，再锁定图集。
- 透明像素/锚点/方向帧错误会让 `dotnet test` 直接失败，而不是靠肉眼发现。
- 世界空间样片仍使用演示数据；真实 `WorldState`/事件绑定是 Gate 2 的下一批
  工作，不得把当前 HUD 数字当游戏状态。
- 接触阴影与地形仍是程序化占位，后续需要正式地表材质与 AO/阴影层。
