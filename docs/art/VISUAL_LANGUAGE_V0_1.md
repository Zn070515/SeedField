# SeedField 视觉设计语言 v0.1 — 两路线对比

> `[PROPOSED]`，尚未得到用户对风格、镜头和色板的正式确认。本文件是制作**可比较的真实 Godot 样片**的可操作设计约束，不是最终风格冻结。

## 1. 体验目标

让玩家产生“这是我设计出来、可以持续运行的精密数字设备和工业文明”的感觉。

本作是一片主控崩溃后的数字世界，但不是抽象算法画布，也不是常见蓝紫霓虹科幻壁纸。
应当实现三种不同距离下的身份识别：远景认功能、中景认结构、近景认制造和损伤细节。

## 2. 核心风格词

- **失落的数字基础设施**：遗址、断裂总线、碎裂封装板、被重新激活的电路地形。
- **精密工业机械**：机械互锁、可见接口、可替换模块、明确输入/输出方向。
- **克制的能量语言**：发光是状态；黑暗材料和反射边缘负责造型。禁止整台设备发光。
- **系统因果视觉化**：能量传输、通信、部件停机、模块受损都可以被实际运行事件解释。

## 3. 相机路线比较（必须在同一场景测试）

### 路线 A：正交斜俯视工业遗址（初始倾向）

- Blender 正交相机，观察角约 **地平线以上 50°–60°**（示例参数，非冻结）。
- 机械顶部 + 少量立面可见；强调结构、投影、材质。
- 风险：移动单位旋转时需要方向图集、分层精灵，或局部实时 3D；瓦片和碰撞地图仍为二维，不得将世界模拟变成等距坐标。

### 路线 B：严格俯视精密工业沙盘（成本对照组）

- Blender 正交相机自上而下 90°；机体可直接在 Godot 中平面旋转。
- 优势：可读性高、方向组合成本低、战术距离判断直观。
- 风险：设备缺少立面/厚重感，需要材质、形体、法线和阴影补足。

### 相机决策门禁

- 两种路线都必须用**同样的种子核心、同样一台模块化战构体和同样一块地形**在真正 Godot 场景截图。
- 分别在远/中/近三个缩放级拍摄；验证遮挡、姿态方向、信息可读性、制作成本与帧时。
- **不得以单张 Blender 效果图选择最终方向。**

## 4. 材质与色板（提案，优先控材质而不是控 RGB）

| 对象 | 材质语言 | 颜色控制 | 避免 |
|---|---|---|---|
| 世界基底 | 低饱和深灰陶瓷、硅基封装地层 | 暗灰/岩黑 | 满屏纯黑/空背景 |
| 主机架 | 哑光石墨、拉丝金属、浅色精密合金边缘 | 黑灰、浅钛 | 玻璃感渐变赛博胶囊 |
| 供电线路 | 铜/金属母排、封闭管路、导电触点 | 暖铜，局部亮芯 | 全线不间断闪烁 |
| 通信组件 | 天线阵列、刻蚀导线、透明封装 | 少量冷蓝/青 | 所有单位都变成蓝色霓虹 |
| 敌方身份 | 不同形体模块和限定标记 | 橙/红点缀 | 整体换皮套橙色透明材质 |
| 损毁设备 | 缺角、烧蚀、暗化、断裂接口 | 灰/煤黑/局部热色 | 只让血条归零 |
| 种子核心 | 稳态几何、分层保护壳、内层载体 | 中性色+小比例稳态辉光 | 无敌金色神坛/能源神球 |

候选色值（只是样片起点）：背景 `#151C22`、壳体 `#333F46`、浅色边缘 `#A7B5B7`、导电铜 `#AD8356`、可交互亮青 `#6BC7CC`、危险暖橙 `#CB7854`。

建议默认画面中自发光区域面积低于主体绘制面积的约 5%–10%（**视觉启发，不作为像素级强制阈值**）。

## 5. 五分支造型语法

| 分支 | 必须有的远景轮廓 | 可解释的中景结构 | 状态变化 |
|---|---|---|---|
| 能源 | 厚重双母线/供能塔 | 输电端口、储能舱、热散片 | 流向、充电、断供 |
| 感知 | 单侧突出探测阵列 | 定向接收头、转台、屏蔽罩 | 扫描/锁定/失效 |
| 通信 | 长轴天线/双极结构 | 中继阵列、导波器、线缆口 | 连接/拥塞/断联 |
| 状态 | 稳定封装块/存储叠片 | 插拔存储、冷却脊 | 写入/保持/损坏 |
| 执行 | 运动机构/驱动接口 | 机械臂、履带、舵机、工具端 | 运动/堵转/维护 |

五分支不允许仅靠图标或颜色区分。组合后的战构体必须仍能感知“哪个模块在起作用”。

## 6. 种子核心——第一视觉锚点

- 不可摧毁是**世界规则**，不是巨型金色护盾球。
- 造型：内核、缓冲保护环、五个可辨认分支接口、逐步外扩的维修/安装平台。
- 内核应在外部全毁后仍然明显完整，但**普通外部线路和防御设备仍可受损**。
- 需要 `idle / regenerating / bootstrap / besieged` 等表现；围困只增加复建限制，绝不画成核心真正死亡。

## 7. 战构体——第二视觉锚点

- 一台可移动中型工体：**主机架 + 可替换传感器 + 可替换武器/工具 + 动力单元**。
- 不依赖任意自由几何拼搭；结构基座可扩展有限的模块插槽。
- 远景按轮廓认“侦察/火力/工程”，近景按模块认改装成果。
- 同一机体更换模块后，至少两个方向下能通过实体外形看出差异。

## 8. 画面层级与低缩放

`世界地形 → 实体轮廓 → 状态反馈 → 选中/任务 → 按需战术覆盖 → 深度调试信息`。

- 默认不常显每台单位的感知圈、射程圈、完整 ID、Tick/哈希/故障统计。
- 选中显示局部射程与信息；高级诊断层可全局开启，保持与目前原型同等可观察性。
- `1280×720` 是目前工程窗口，不代表最终只支持这一分辨率；需测试 `1920×1080` 和高 DPI。
- 需提供灰度/色觉模式下的形体识别验证，禁止纯青/橙区分文明。
- 核心设施默认缩放应至少具备肉眼可认的轮廓；无需观察到每颗螺丝，但不能只剩 13px 的圆点。

## 9. 如何识别“假精致”

拒绝以下替代方案：

1. 单纯增加大量氛围粒子、霓虹光条、六边形和 UI 描边。
2. 一次性生成 50 张风格不一致的 AI 图，每个对象光源、视角、材质、比例不同。
3. 非游戏内概念插画冒充可装配的设备贴图。
4. 设备看着复杂却无法解释模块功能或物料输入/输出。
5. 只有 2× 近景好看，正常缩放完全无法辨认。

## 10. 可参考但不可复刻

- Factorio：机械实体的体量感、系统可读性。
- Into the Breach：有限画面内的清晰对象、选中与威胁层级。
- Mindustry：基础模块和连线密度的可控性。

参考视觉原则，不得直接复用或临摹商业游戏现成资产。
